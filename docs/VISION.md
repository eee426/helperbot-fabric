# 长期方向：从“工业机器人”到“有记忆的电子玩家”

写给以后接手的人和开发 AI：这是作者对这个模组的长期设想，以及 2026-11-11 时的一次可行性评估。它不是要先读完才能动手的文档，也不是待办清单；每一层都要一点一点做，做到哪一层再细看哪一层。

## 一句话

现在的 HelperBot 是一个“帮你干活的工业机器人”：你说要什么，它自己规划、采集、合成、带回来。最终想要的，是一个**能陪你玩、记得你们一起做过什么的电子玩家**：会聊天，会守家、种田、下棋、跟着你，长着好看的皮囊，背后由大模型驱动，手脚是这个模组。

## 分层

从下往上，每一层只用下面一层，不绕过它。

| 层 | 内容 | 现在 |
|---|---|---|
| 1. 内核 | 寻路（`LocalPathfinder`）、物品规划（`CraftPlanner`）、反射（换气、自卫、吃东西、补方块）。每个问题只有一个地方回答 | 有，约 2.2 万行，154 个回归场景（2026-11-14） |
| 2. 动作 | 内核会的移动方式：爬梯子、开门、潜行、水桶落地、跑跳、坐船、鞘翅…… | 部分有；新动作计划见 `PERF_BACKLOG.md`（暂缓） |
| 3. 任务 | 一单活：采集、打猎、合成、熔炼、舀、过来……（`task/`） | 有 |
| 4. 接口 | 给外面调用的稳定入口：下单、查状态、取消，结构化的事件流（不是聊天框里的字） | 只有聊天命令（`/bot get`、`/bot come`……），日志打在聊天框 |
| 5. 大模型 | 玩家用自然语言说话，大模型挑接口调用（“盖房没木头了” → 要 32 个原木），把事件流讲成好听的话（美化层） | 没有 |
| 6. 家园能力 | 跟随、守家、保护主人、种田、下棋…… 参考车万女仆（Touhou Little Maid）的模块 | 跟随、自卫有雏形（`ComeTask`、自卫反射），其他没有 |
| 7. 外观 | 适配 YSM（Yes Steve Model），换皮囊 | 没有 |
| 8. 记忆和陪伴 | 长期记忆（实时摘要：和主人在这个世界里做过什么），闲聊，更自由地调用内核（给个坐标就走过去） | 没有 |

## 设计理念

- **地基要稳，再往上加。** 上面几层都是对内核的调用。内核的 bug 到了大模型那一层会被放大：大模型看不懂“这一步比预计慢太多”，只会一遍遍重试。所以先有一个真正的稳定版，再往上盖。
- **内核给唯一的答案，外层只调用。** 能不能到、怎么做最省、现在保不保命，各只有一个地方回答。外层（任务、大模型、家园模块）只负责提要求、排先后、兜底，不自己另算一套。
- **规划和动手可以分开，但规划必须覆盖所有动作。** 出过的大部分 bug，都是“有一段动作没人规划过”或者“规划和执行用的标准不一样”（见 `BUGS.md`）。
- **简单的闭环比复杂的预判耐用。** 能靠“试了不行就记下、换下一个”收住的地方，就不加提前计算；收不住的（每个地方看起来都一样、都会算错），才让规划答对。
- **游戏数据，不靠猜。** 时间按真实刻数，知识从游戏数据里读，不凭感觉调系数。
- **一次只加一样。** 每样新东西先写场景，过全量回归和规划扫描，再加下一样。

## 各层的可行性（2026-11-11 的评估）

### 1. 稳定版（现在这一步）

最值得做，也是后面所有事的前提。当前状态：151 个回归场景全过，规划扫描稳定，已知问题都记在 `BUGS.md`，而且大多是罕见情况。剩下的主要是在游戏里多玩、多报 bug。

建议给“稳定”定一个可以核对的标准，比如：连续几次正常游玩没有发现新的内核 bug；全量回归 100% 通过；`BUGS.md` 里每一条都标了“修”或者“接受”。

### 2. 动作

这一层是内核改动，不是外层。每个动作都要改三处：规划里加一种走法（`path/moves`）、执行层加一个执行器、再加场景。难度差别很大：
- **较容易**：斜着游、斜着走、爬梯子和藤蔓、开门和栅栏门（读门的方块数据，铁门自动排除）。
- **中等**：潜行（贴边不掉，挖脚下时不滑）、跑跳（跳的距离和落点要按原版物理算准）。
- **较难**：水桶落地（时机、维度能不能放水、落下时的物理）、坐船（多一个“在船上”的状态，搜索量会成倍增加）、鞘翅（飞行物理、起飞、落地，基本是另一套寻路）。

建议在第 4 层定接口之前，把想要的动作加完，因为动作会改变内核能回答什么。

### 3–4. 接口

工作量中等，但非常关键：它决定了大模型能做什么、不能做什么。要做的事：
- 把现在的聊天命令整理成结构化的接口：下单（要什么、要多少、什么模式）、查状态、取消、去某个坐标。
- 把日志从聊天框改成事件流（开始了什么、卡在哪、完成了、失败原因），带机器可读的字段。聊天框只留给玩家看的话。
- 接口要有权限和边界：保护区块、禁止的动作，这些规则在接口层就生效，不能依赖大模型自觉。

### 5. 大模型

技术上可行，主流大模型都支持“工具调用”，正好对应接口。要考虑的问题：
- **在哪儿调用**：服务器端还是客户端，API 密钥放在哪，多人服务器上谁付钱。
- **不能卡游戏**：调用必须异步，不能在服务器主线程上等结果。
- **延迟和费用**：每句话一次调用，事件流不能每条都发，要先汇总。
- **安全**：大模型只能调用接口，接口本身守规则；坐标、数量这些参数要校验。
- **美化层**：把事件流讲成“主人爱听的话”，这一层最简单，但要注意别把失败也美化掉，玩家需要知道真实情况。

### 6. 家园能力（参考车万女仆）

创意很好，但**不是“直接搬过来”**，要先确认三件事：
- **许可**：车万女仆的代码和美术素材（模型、贴图、声音）的许可可能不一样，要分别核实，不要只看仓库首页。
- **加载器和版本**：它的主线是 Forge/NeoForge，这个模组是 Fabric 1.21.11，引用的 API 不能直接通用。
- **实体类型不同**：女仆是自定义实体，行为写在实体的 AI 目标（Goal/Brain）里；我们的机器人是一个假玩家（`ServerPlayer`），行为写在任务和内核里。所以它的模块大多要按思路重写，而不是照搬代码。

各模块的难度：
- **跟随、保护主人、守家**：容易，这里已经有寻路和自卫反射，只要加任务和巡逻范围。
- **种田**：中等，用现有的采集和放方块就能做；以后如果内核加了“站在原地干活”的通用步骤，会更顺。
- **中国象棋**：基本独立于内核（界面加棋局逻辑），可以单独做。要核实它的代码和素材能不能用。

### 7. 外观（YSM）

取决于 YSM 有没有对外接口，以及它在 Fabric 1.21.11 上能不能给一个假玩家用。YSM 本身是闭源的，能不能适配要先做个小实验：装上 YSM，看客户端会不会给机器人渲染选定的模型。能直接用最好，不能就要等 YSM 提供接口。

### 8. 记忆和陪伴

可行，主要工作在大模型那一侧：
- **记忆**：按事件流定期写摘要（今天一起挖了什么、去过哪），每个世界存一份，下次对话时取出相关的部分。
- **闲聊**：纯大模型能力。
- **更自由地调用内核**：比如“走到某个坐标”，内核本来就有（`goTo`），只要通过接口开放出来，并守住接口的规则。

## 离最终目标还有多远（粗略）

- **内核和任务**（第 1、3 层）已经是这个项目最难、最大的部分，大致完成。剩下的是稳定和打磨。
- **动作**（第 2 层）是剩下的内核工作里最大的一块，越往后越难，尤其是鞘翅和坐船。
- **接口、大模型、美化、记忆**（第 4、5、8 层）是全新的代码，但都建在现有内核之上，技术上没有未知数，主要是工作量和设计取舍。
- **家园能力和外观**（第 6、7 层）的不确定性最大，取决于别人的许可和接口，要先做小实验再定。

所以你说得对：剩下的大多数是外层。但有两点要注意：动作层仍然是内核工作，而且是难的那部分；接口层虽然代码不多，却决定了上面所有东西能做什么，值得认真设计一次。
