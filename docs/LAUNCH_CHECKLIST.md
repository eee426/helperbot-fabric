# 上线前限制清单

> 贝塔阶段为了测试能力上限，放开了很多限制。**部署到正式服务器之前，必须逐项处理这份清单。**
> 每加一个新的"放开"功能，都要同步更新这里。
>
> 最后更新：2026-10-31

图例：🔴 必须改，否则会破坏存档或被滥用 · 🟡 强烈建议 · 🟢 确认一下就行

## 1. 规则与权限

| | 项目 | 现状（贝塔） | 上线前要做 | 位置 |
|---|---|---|---|---|
| 🔴 | 默认规则 | `OPEN`：什么都能挖、能搭 | 默认改为 `STRICT`，或者改成读配置文件 | `guard/Rules.java` |
| 🔴 | `/bot rules` 指令 | **任何玩家**都能切换成 open | 要求 OP 权限，或者正式版里直接删掉 open | `command/BotCommands.java` |
| 🔴 | 规则不持久化 | 重启后恢复默认 | 存进配置文件，避免"以为是 strict，其实是 open" | `guard/Rules.java` |
| 🟢 | `/bot protect`（保护区块） | 任何玩家都能**增加**保护（指令或遥控模组的地图）；**取消**只能在服务器后台按 ID（`/bot protect remove <ID>`，权限 4） | 2026-11-02 已按这个做。以后可考虑记录是谁保护的 | `command/BotCommands.java#protectChunk` |
| 🟢 | 冒用机器人的名字 | 两道：①真玩家用机器人的名字（不分大小写）登录，在登录阶段就拒绝（还没进世界，不会触发别的模组）；②漏进来的（主要是地毯假人，不走登录）每秒受到等于血量上限的伤害（/kill 那种，不受护甲、附魔、药水、图腾影响，不磨护甲），死掉走正常流程。只针对玩家列表里的玩家，同名的生物不受影响 | 注意：离线服里名字就是账号，冒名者载入的是**机器人的背包**，死的时候会撒在原地。所以第①道很重要（还能避免把机器人挤下线），别删 | `HelperBot.java`、`guard/NameGuard.java` |
| 🟡 | 公共机器人（测试阶段） | 全服一只，谁都能召唤、移除、下任务、打断别人的任务 | 测试阶段有意如此；正式服再考虑"只能停自己的任务" | `command/BotCommands.java` |
| 🟡 | 保护区块里的灵魂状态 | 机器人在保护区块里对服务器来说算旁观者（不触发机关、不被怪盯、不被推、不捡东西、不攻击），但仍是生存模式、别人看得见；会受伤（比如岩浆）。依赖服务器设置 `spectatorsGenerateChunks` 为默认的 true，否则它在保护区块里时周围区块可能不加载 | 正式服确认这个设置；确认显示正常（不同客户端模组下） | `bot/BotPlayer.java#isGhost` |
| 🔴 | 空手跟远程怪打 | 被骷髅这类远程怪盯上时，没有武器也会追过去打，测试里被"Parched"（1.21.11 的新骷髅）射死过 | 没武器时远离远程怪，或者先躲起来 | `bot/BotPlayer.java#combat` |
| 🟡 | `/bot spawn / remove / get / come / cancel` | 任何玩家都能用，而且只有一个全局机器人，谁都能指挥、谁都能取消别人的任务 | 改成每人一个机器人，或者记录主人、只听主人的 | `bot/BotManager.java` |
| 🟡 | 右键编辑背包 | 任何玩家都能打开机器人背包拿东西 | 只允许主人（和 OP）打开 | `HelperBot.java` |

## 2. 破坏与放置（open 模式下的行为）

| | 项目 | 现状（贝塔） | 上线前要做 | 位置 |
|---|---|---|---|---|
| 🔴 | 能挖任意方块 | 除基岩、TNT、紧挨岩浆的方块外**全部能挖**，包括玩家建筑、箱子（东西会散落一地） | strict：只挖天然地形 + 不在放置记录里的方块 | `guard/Guard.java#canBreak` |
| 🔴 | 放置记录 | **还没做** | 记录玩家放置的每个方块，机器人一律不挖 | 待开发 |
| 🔴 | 操作日志 / 撤销 | **还没做** | 记录机器人挖过和放过的方块，支持 `/bot undo` | 待开发 |
| 🔴 | 搭桥、垫柱子 | 用完**留在原地**，野外会到处是土柱和土桥 | 正式版：任务结束后拆掉自己搭的方块，或者只在开关打开时允许 | `bot/MovementController.java#placeBlock` |
| 🟡 | 有风险的挖掘 | open 下允许挖沙子下面、水边的方块（只是代价高） | strict 下禁止（已实现，确认生效） | `guard/Guard.java` |
| 🟡 | 打猎探索 | 附近没有要打的动物时：去 1000 格内最近的"它最多的群系"，没有就在方圆 500 格内走着找；可能生成新区块（占硬盘） | 确认 500/1000 格合适；多人各有机器人时要考虑总量 | `task/HuntTask.java`（`EXPLORE_RADIUS`、`EXPLORE_MAX_RADIUS`） |
| 🟡 | 堵井口 | open 下在水下挖井时，会在井口放一块方块堵水，用完不收回；海底会留下一个被堵住的竖井 | strict 下不会发生（放方块要 open）；上线前决定是否要事后收回 | `bot/MovementController.java`（`seal`） |
| 🟢 | 水下扣血 | 为了把一次潜水做完，允许溺水扣血，但血量不低于 12 | 确认这个下限玩家能接受 | `path/Air.java`（`KEEP_HEALTH`） |
| 🟡 | 就地收集方块 | 没路时会挖身边的方块（会挖出坑） | strict 下关闭，或者只挖天然地形 | `bot/MovementController.java#gatherTick` |
| 🟡 | 种子比对兜底 | **还没做** | 可选的第二道保护 | 待开发 |
| 🔴 | 采集任务的目标方块 | `/bot get` 会去挖**任何**掉落目标物品的方块。strict 下也只排除"有方块实体的方块"和"玩家放的树叶"，所以**玩家用该方块搭的建筑也会被当成矿来挖**（比如要樱花木板时，可能拆别人用樱花木板盖的房子） | 依赖放置记录：玩家放的方块一律不当作采集目标；在那之前，正式服至少要求保护区覆盖所有建筑 | `guard/Guard.java#canHarvest` |
| 🟡 | 自带的工作台、熔炉 | 合成/熔炼时把自己的工作台或熔炉放在身边，用完挖回来。**strict 规则下也允许**（因为会收回）。没有镐时熔炉挖不回来，会留在原地并告诉玩家 | 确认能接受；确认收回时不会误挖别人的工作台（只挖自己放的那个坐标） | `task/Station.java` |
| 🟡 | 为了看见目标而挖开挡路的方块 | 目标被挡住时，会先挖掉挡在中间的方块（按 `canBreak` 规则） | strict 下确认只会挖天然地形 | `task/GatherTask.java#mine` |

## 5. 服务器负担

| | 项目 | 现状（贝塔） | 上线前要做 | 位置 |
|---|---|---|---|---|
| 🔴 | 远程搜索 | 取水会搜索 **1 万格**内的水域并走过去，一路**生成新区块** | 给出配置上限；云服务器上建议先限制在 2000～3000 格 | `task/FetchWaterTask.java#MAX_DISTANCE` |
| 🟡 | 寻路扩大范围 | 最大 ±64 格、20 万节点，按每刻 8 毫秒分摊 | 在云服务器上观察 TPS 和内存，必要时调小 | `path/LocalPathfinder.java#LEVELS` |
| 🟡 | 后台线程找群系 | 在主线程以外调用（原版 `/locate` 在主线程上运行） | 在服务器上长时间运行，确认没有报错；有问题就改回主线程并限制搜索半径 | `task/FetchWaterTask.java#find` |
| 🟡 | 机器人加载区块 | 和真人玩家一样，会让周围的区块保持加载 | 玩家都下线时，暂停任务或者移除机器人 | 待开发 |
| 🟢 | 找水扫描 | 附近 48 格扫描一次，在主线程上 | 观察有没有卡顿 | `task/FetchWaterTask.java#nearestWater` |
| 🟢 | 掉落分析 | 服务器启动时（以及 `/reload` 后）一次性模拟所有方块的战利品表，建成总索引，日志里会打印耗时；之后查询只是查表 | 在云服务器上看一眼启动日志里的耗时 | `knowledge/DropAnalysis.java` |
| 🟡 | 合成规划 | 每一步之后都会重新规划，单次规划最多探索 4 万个节点、最多 2 秒（只是保险；正常几十毫秒，开服后第一次几百毫秒。超时用目前最好的方案，并写进服务器日志）；用时超过 100 毫秒会把耗时明细记进 `/bot log`。开发时可设环境变量 `HELPERBOT_BENCH` 跑规划基准（`knowledge/PlanBench.java`） | 观察复杂物品（比如染色的东西）规划时有没有卡顿；日志里有没有"planning … hit the time limit" | `knowledge/CraftPlanner.java` |
| 🟡 | 开发用的测试入口 | 环境变量 `HELPERBOT_BENCH`（规划基准）和 `HELPERBOT_SCENARIOS`（自动测试场景，会造地形、召唤机器人、加速游戏、跑完关服）。没设这两个变量时完全不起作用 | 确认正式服务器上没设这两个变量；或者上线前把 `test` 包移出正式 jar | `knowledge/PlanBench.java`、`test/` |
| 🟡 | 机器人日志写进服务器日志 | 机器人的每条行动日志都以 INFO 级别写进 latest.log（方便查罕见 bug） | 多个机器人时日志量会很大：改成 DEBUG 级别或加开关 | `bot/BotPlayer.java#log` |
| 🟡 | 采集远程搜索 | 和取水一样：1 万格内找群系；找不到就在周围最多约 480 格内绕圈探索 | 同"远程搜索"那一条 | `task/GatherTask.java` |
| 🟡 | 掉落物 | 会捡起**所有**同名物品，不管是谁的（比如玩家扔在地上的） | **strict 下现在也一样**：2026-11-03 重写掉落物时去掉了“只捡自己挖出来的”。上线前要 strict 限制的话得加回来 | `task/DropFetch.java#nearby` |
| 🟡 | 地上的东西算资源 | 任务要的东西，只要在搜索范围内、不在保护区块里，不管是谁的，都和方块、怪物一样可以专门跑去拿（比如玩家放在地上留给朋友的）。不是路过顺手，是主动去 | 2026-11-03 玩家同意；上线前确认要不要限制 |
| 🟡 | 探索会生成新区块 | 找不到东西时，机器人会在出发点方圆 2000 格内走动最多 10 分钟（圈内没有这种群系时，会走到最远 1 万格外），一路生成新区块，存档会变大（估算每次约 30MB，未实测） | 确认存档增长可接受 | 2026-11-04 |

## 7. 公平性（"不作弊"的承诺）

| | 项目 | 现状 | 说明 |
|---|---|---|---|
| 🟢 | 移动速度、跳跃、重力 | 按原版上限 | 已实现 |
| 🟢 | 疾跑与饥饿 | 饥饿值 > 6 才疾跑；疾跑、游泳、跳跃按原版消耗饥饿 | 已实现 |
| 🟡 | 远距离寻路不求最优 | 目标在搜索范围外时用加权搜索（路线代价最多是最优路线的 1.4 倍），到范围边缘就停 | 确认路线质量可以接受 |
| 🟢 | 挖掘、放置 | 走原版生存流程，服务端校验 | 已实现 |
| 🟡 | 水下一次搜完 | 下水前一次搜完所有目标，放在后台，机器人在水面等；上限 200 万格，测试里 120 格见方的海要 3.6 秒；路上不挖不放，例外是水面上的冰 | 真实海洋里看日志“一次搜完”的用时，确认能接受 | `bot/MovementController.java` |
| 🟡 | 水流、击退 | 直接控制坐标，**不受水流和击退影响** | 轻微作弊，确认能接受，或以后补上 |
| 🟢 | 氧气、溺水、摔落伤害 | 原版氧气和溺水规则；摔落伤害按原版公式模拟 | 已实现 |
| 🟢 | 远程搜索 | 只读取世界生成参数（和 `/locate` 一样），不偷看箱子里有什么 | 确认能接受 |
| 🟡 | 结构知识 | 知道每种结构可能有什么（来自游戏数据，像熟悉游戏的玩家）；到了结构附近，隔着墙也知道没开过的箱子在哪，但打开前不知道里面有什么 | 确认能接受，或改成看见才算 |
