# HelperBot 架构

> 最后更新：2026-11-14（按提交 8b4fb4a 的代码）

服务端约 2.2 万行（90 个文件，其中测试场景约 3,100 行），客户端遥控器约 1,300 行。服务端分 5 层。**上层只调用下层，下层不知道上层的存在。**

每条任务链实际怎么走、每个函数被测试跑过多少，看 `HelperBot 行为图.html`。

```
 玩家
  │  /bot 指令、右键打开背包、客户端遥控器（H 键）
  ▼
┌──────────────────────────────────────────────────────────┐
│ ① 入口层   HelperBot, command/BotCommands, BotInventoryMenu │  听玩家说什么
└──────────────────────────────────────────────────────────┘
  │ 创建任务
  ▼
┌──────────────────────────────────────────────────────────┐
│ ② 任务层   task/*                                          │  "要做什么"
│   AcquireTask（总指挥）→ GatherTask / HuntTask / CraftStep  │
│     / SmeltStep / UseStep / ScoopStep                      │
└──────────────────────────────────────────────────────────┘
  │ 查资料                          │ "走到那里""挖这块""放这块"
  ▼                                 ▼
┌───────────────────────┐   ┌──────────────────────────────┐
│ ③ 知识层 knowledge/*   │   │ ④ 身体层  bot/*               │  "怎么做"
│ 东西从哪来、怎么做出来 │   │ BotPlayer：生存优先级         │
│ （只读游戏数据）       │   │ MovementController：走/挖/放  │
└───────────────────────┘   │ Hands：挖和放  Body：物理     │
                            └──────────────────────────────┘
                                    │ 找路           │ 能不能挖/放
                                    ▼                ▼
                            ┌──────────────┐  ┌──────────────┐
                            │ ⑤ 寻路 path/* │  │ ⑤ 规则 guard/*│
                            └──────────────┘  └──────────────┘
```

依赖只能往下走，同层之间也不能绕回来（2026-11-10 按 import 核对过，没有违反的）：

| 这一层 | 可以用 | 不能用 |
|---|---|---|
| `guard` | 只用游戏本身 | 其他所有层 |
| `path` | `guard` | `knowledge`、`bot`、`task` |
| `knowledge` | `path`、`guard` | `bot`、`task` |
| `bot` | `path`、`guard` | `knowledge`、`task` |
| `task` | 以上全部 | |

下层要用上层的东西时，把它放到下层：`bot/BotTask` 是身体层定的接口，任务层来实现；`guard/InDimension` 是规则层定的接口，`path/Snapshot` 来实现；`path/moves/Planner` 是动作定的接口，`LocalPathfinder` 来实现。各层都可以用 `HelperBot.LOGGER`，它只是日志，不算依赖。

### 三个内核

能不能到、怎么做最省、现在保不保命，各只有一个地方回答（见行为图的“寻路内核”“规划内核”和“换气”）：

| 内核 | 回答 | 在哪 |
|---|---|---|
| 寻路 | 能不能到、走哪条路 | `path/LocalPathfinder`（A*、洪水），`bot/RouteSearch` 选搜索方式、读结果 |
| 规划 | 拿到 N 个某物最省时间的一串动作 | `knowledge/CraftPlanner` |
| 反射 | 换气、自卫、吃东西 | `bot/BotPlayer` 的 `breathe` / `combat` / `tryEat` |

任务层只排序、省时间、或者让它活下来，不自己判断“到不了”“做不出”。

## ① 入口层：听玩家说什么

| 文件 | 作用 |
|---|---|
| `HelperBot` | 模组启动：注册指令、右键事件；开服和 `/reload` 时预热知识层（配方、生物掉落、群系、结构）和 `path/BlockTable` |
| `command/BotCommands` | 所有 `/bot ...` 指令，把玩家的话翻译成一个任务（见下表） |
| `bot/BotManager` | 生成、删除机器人，加载它的存档数据 |
| `bot/BotInventoryMenu` | 右键打开的背包界面 |
| `bot/FakeConnection` | 假的网络连接（机器人没有客户端） |
| `bot/NameGuard`, `bot/ZoneReminder` | 每秒看一次：有人冒用机器人的名字；机器人在场但一个保护区块都没有 |

指令：`spawn` `remove` `status` `perf` `log` `cancel` `come` `get <物品> [数量] [模式]` `rules open|strict` `debug path` `restrict block|portals` `where` `protect`（`list` `chunks` `query` `remove` `show`）。

### 客户端遥控器（`client/`，可选）

服务端不依赖它；装了的玩家按 H 用按钮拼出 `/bot` 指令发出去，不用打字（手机启动器也能用）。

| 文件 | 作用 |
|---|---|
| `HelperBotClient` | 注册 H 键 |
| `BotMenuScreen` | 第一级菜单 |
| `ItemPickerScreen` | 选物品：先按维度（数据来自 `/bot where`，见 `ClientWhere`），再按创造模式物品栏分类 |
| `AmountScreen` | 选数量和模式，发出 `/bot get` |
| `ChunkMapScreen`, `ClientZones` | 俯视地图上选区块保护（数据来自 `/bot protect query`） |
| `TouchScreen` | 手指和鼠标都能用的界面基类 |

## ② 任务层：要做什么

每个任务每刻被调用一次，返回"还在做 / 做完了 / 失败了"。

| 文件 | 作用 |
|---|---|
| `AcquireTask` | **总指挥**。`/bot get` 用它：问规划内核要一份计划，只执行第一步，做完一步重新规划。一单最多 80 步；同一物品失败 3 次就从计划里去掉这个来源 |
| `GatherTask` | 找到某种方块，内核确认能到才出发（埋着的，从站位要原地挖掉哪些、按什么顺序，内核和路线一起检查，交给它原地挖：挡着的是想要的东西就当成目标、带全套检查挖，别的用最快的工具；挡着的不在清单里就重新问内核），挖之前核对手里的东西，挖。附近没有时交给 `Explorer`；没有群系长它，就去用它建的结构，最多 3 处。去了没找到、或者一直去不了的结构，这一单里不再去找这样东西（按物品记，整单共用） |
| `HuntTask` | 找到会掉这种东西的生物，内核确认能到，追上去打死，或者对它用桶、碗。附近没有时：动物交给 `Explorer`；怪物把原地也当成一处（走过去的时间是 0），和还没去过的地方用同一个公式比，原地不比最好的去处慢才等刷新（白天露天先等天黑），否则去别处；只在结构里刷的去结构里找，最多 3 处 |
| `DropFetch` | 地上的掉落物当作一个来源，和方块、生物放在一起比；走过去，物品动了就重新规划 |
| `Explorer` | 附近没有时去哪找：用种子算 2000 格内的群系地图（每 48 格一个点，不加载区块），选最快拿够数的地方 |
| `FarBiome` | 2000 格的地图里一处都没有时，让游戏在 1 万格内找最近的那种群系（后台算）。采集、打猎、装东西共用：出错和“没有”分开说；就在脚下的不算一趟，改成把已加载的范围看一遍。这一趟路上受阻，打猎和装东西从走到的地方再出发，最多 3 次（采集 4 次） |
| `OutOfReach` | 这一单查实到不了的目标（记忆本）。每条记着它凭什么成立，条件变了才再看 |
| `CraftStep` / `SmeltStep` / `Station` | 合成、熔炼；需要时自己放工作台/熔炉（身边放不下就找干地），用完收回 |
| `UseStep` | 用东西做出来：斧子去皮、混凝土粉末浇水、空地图 |
| `ScoopStep` | 用容器装：桶装水、岩浆和细雪，玻璃瓶装水 |
| `ComeTask` | `/bot come`，也是一单结束后的回程：走到玩家身边，到不了就原地等 |
| `MineCost` | 这只机器人挖这一块要花多少：用它手里的工具和气，给采集目标排序 |
| `RestockStep` | 补方块反射层的活：用采集任务在附近、只从地面挖，补到够数 |

## ③ 知识层：东西从哪来（不动世界，只读游戏数据）

| 文件 | 回答的问题 |
|---|---|
| `DropAnalysis` | 挖哪种方块会掉这个东西？用什么工具？ |
| `MobDrops` | 打哪种生物会掉这个东西？它在哪些群系出生？ |
| `RecipeIndex` | 哪些配方能做出这个东西？ |
| `CraftPlanner` | 综合以上，**算出最省时间的计划**（挖/打/合成/熔炼/使用/装水），按真实游戏刻算，带下界剪枝 |
| `BiomeHints` | 每个群系每个区块平均有多少某种方块：来自地物的放置次数和大小、地表规则、低温结冰、海（海洋和河流在海平面以下，灌满这个维度的默认流体）。只算“放下的方块”，不算“作为条件的方块” |
| `Habitat` | 东西在世界的哪一层（地表、地下、水下）：所有“去远处”都经过它，走到对的高度，不只是对的 x/z |
| `BlockScanner` | 附近已加载的区块里有没有 |
| `BuildingSources` | 哪些方块能拿来搭路：地面本身和挖它掉的东西，全部从方块标签、掉落表、维度的生成设置推出来 |
| `Obtainability` | 这东西生存模式能拿到吗？（基岩、命令方块直接拒绝） |
| `Interactions` | 对方块或生物用东西能得到什么：斧子的去皮表、混凝土粉末遇水变成什么、每种流体的桶、桶能装起的方块（细雪），以及拿桶、水桶、碗对每种生物用一下的结果（造一个不放进世界的生物、假玩家去用，问游戏要答案）。玻璃瓶装水和空地图只写在游戏代码里，单独写明 |
| `WhereFrom` | 每个物品从哪来：只靠主世界、要去地狱、要去末地、拿不到。和规划器“世界里有没有”同一套推法，按维度各算一遍。给遥控器的选物品界面用（`/bot where`） |
| `StructureIndex` | 哪些结构里有什么：结构 → 模板池 → 模板，读出方块和生物。全部来自游戏数据，模组结构同样适用。规划器只在别处拿不到时才去结构里找 |
| `StructureOdds` | 结构里**有它的机会**：开服后在后台让游戏在内存里把每种结构拼 100 次（不放方块、不加载区块），数每种方块出现在几成的结构里（地狱疣：要塞约八成，堡垒约四分之一）。存进存档的 `data/helperbot-structure-odds.json`，带"指纹"（游戏版本、种子、结构和模板清单），下次开服对得上就直接读，文件没了、坏了、加了模组就重建；先写临时文件再改名，不会留下半个文件。规划去结构的成本按"典型距离 ÷ 机会"算，采集选结构也按这个比。表没好之前不接 spawn / come / get / where |
| `PlanBench` | 开发工具：设了环境变量 `HELPERBOT_BENCH`，开服时规划几样东西、记下用时，然后关服 |

## ④ 身体层：怎么做

### BotPlayer：每刻的优先级（最重要的一张表）

每刻从上往下问，**谁说"我在忙"，下面的就都不执行**：

| 顺序 | 层 | 什么时候接管 |
|---|---|---|
| 1 | 换气 `breathe` | 水下气只够游上去；游不出去时才能挖开头顶 |
| 2 | 自卫 `combat` | 有怪在打它、盯上它（远程 10 格内追过去 / 近战够得着） |
| 3 | 吃东西 `tryEat` | 吃了能用上至少 75% 的东西才吃（边走边吃） |
| 4 | 补方块 `restock` | 搭路的方块少于 32 个，或者寻路说"要搭路、方块不够"，而且附近有能挖的地面（每 5 秒看一次）：补到 64 个。只在两步之间、站稳的时候接管 |
| 5 | 任务 `task.tick` | 以上都没事。背包快满时先整理 `tidyInventory` |
| — | 移动 `movement.tick` | 每刻最后执行，真正挪动身体（换气层自己调用） |

捡掉落物不再是单独一层：地上的东西是任务的一个来源（`task/DropFetch`）。`bot/Loot` 只在方块挖掉的那一刻记下掉了什么，给 `GatherTask.checkDrop` 核对掉落表。

上层（自卫）要临时去别的地方时，用 `engage` 借用移动；结束时用 `disengage` 把任务原来的目的地还回去。补方块用 `lend` / `takeBack`，同样把任务原来的目的地原样还回去，任务不知道被打断过。

### 搭路的方块

| 档 | 数量 | 谁管 |
|---|---|---|
| 上限 | 120 | 路过时顺手捡（`BotPlayer.wantsPickup`），到 120 不再捡 |
| 补货线 | 少于 32 | 补方块反射层接管 |
| 补到 | 64 | 补方块反射层停手 |

数字都在 `path/BuildingBlocks`。哪些方块能拿来搭路由 `knowledge/BuildingSources` 从游戏数据推出来：地面本身（方块标签里主世界、地狱的石头和泥土，加上每个维度生成地形用的默认方块：石头、地狱岩、末地石），挖了掉的东西（石头掉圆石、草方块掉泥土；矿石掉的是矿物，自动排除），只要完整、不受重力、没有方块实体的；木板也可以用。

补方块本身是任务层的 `task/RestockStep`：用采集任务（加了"只在附近、只从地面挖"的开关），最近的一种先采，不够再换下一种，附近挖完了有多少算多少，不去远处找。挖不到的地方记进这一单的"到不了"记录（`OutOfReach`），下次看的时候就不算它。身体层不能调用任务层，所以由身体层定接口 `bot/Restock`，任务层开服时注册上来。

### 移动的模块

| 文件 | 只负责 |
|---|---|
| `MovementController` | 跟着路线走：对外的 `goTo`、`status`、`follow`，走一步、看门狗、借用移动（打架、补方块）；没路又缺方块时停下等补方块 |
| `RouteSearch` | 选哪种搜索、怎么看结果：全量搜索、窗口、洪水、保护区、边走边算下一段 |
| `StepExecutor` 和 `WalkStep` / `PillarStep` / `BreatheStep` | 每种路线步骤怎么一刻一刻执行：走/跳/落、往上垫、停下换气（游泳是 `MovementController` 自己的） |
| `Hands` | 挖和放，全局总闸的执行层，工具选择 |
| `Body` | 碰撞、重力、摔伤、浮沉、直接往上游 |
| `Sight` | 能不能打到一个实体：够得着且看得见，当作寻路目标用 |
| `Perf` | 只测量：每刻时间花在哪（`/bot perf`） |

加一种新的移动方式：`path/moves` 里加一个动作，`PathStep.Type` 加一种步骤，这里加一个 `StepExecutor`。

## ⑤ 底层

### 寻路 `path/`

| 文件 | 作用 |
|---|---|
| `LocalPathfinder` | A* 寻路：在一块范围内找一串步骤；代价是真实刻数；水下每个节点还带着"剩余空气"，以及这条路线自己挖开、已经进水的格子（`Wet`：冰挖掉变水、挨着水挖开；判断头干不干、站没站稳、挖多慢都按水算）。一格深的水里站在水底（`surfaceFeet`，身体 `Body.fall` 用同一个），含水的矮方块也算地面；能攀爬的方块（梯子、藤蔓，`climbable`）不算地面（补丁，做爬梯子时要重新看，见 `PERF_BACKLOG.md` 阶段 8）。同一步失败 3 次或超时的终点记进“暂时绕开”的名单（`MovementController.avoidUntil`，30 秒），规划通过落脚高度和能不能穿过来避开；挖掘步骤还没接上（见 `BUGS.md`）。找到一个够得着目标、但视线被挡着的站位时，原地要挖掉的方块（连同挡着它们的，`MineSpot.clearing`）按路上挖掘的规矩一起检查（`workHere`：能挖、不靠岩浆、头干、一口气、不挖自己脚下），通过了随路线一起交出（`Result.work`），由任务去挖；路线本身只有移动。洪水搜索（不挖、气最多的先走）也在这里 |
| `moves/*` | 搜索会的动作：走、游、挖、往下挖、搭桥、往上垫。`Moves.ALL` 是全部，`Planner` 是动作能问搜索的东西 |
| `PathStep`, `Candidate`, `PathGoal` | 一步、一个候选（代价和真实刻数分开记）、路线可以在哪结束（`toClear`：到那里还要原地挖掉什么） |
| `PathJob`, `Snapshot`, `Worlds` | 后台线程：主线程复制附近的区块（`Snapshot`），所有机器人共用 1 个后台线程在副本上算；`Worlds` 让同一段代码在真实世界和副本上都能跑 |
| `TravelEstimate` | 搜索范围外那段的估算：在地下就比较一路挖过去和先上地面再跑哪个快 |
| `Air`, `Escape` | **水下的气量规则**：空气预算（剩余空气 + 允许扣的血）必须够它从当前位置出水；`Escape` 算"从这格游到能呼吸要多少刻"，不算挖。寻路、换气、选目标都用它 |
| `MineSpot` | **站在哪能挖到这一块**：选目标、规划器、走过去都问它，所以说法不会不一致 |
| `Mode` | 安全 / 普通 / 激进三种模式的参数 |
| `BlockTable` | 开服和 `/reload` 时给每种方块状态算好“空不空、多高、干不干净”，寻路查表 |
| `BreakTimes`, `BuildingBlocks` | 挖一块要多久；背包里哪些方块可以拿来搭路、留多少（见上面"搭路的方块"） |

### 规则 `guard/`

| 文件 | 作用 |
|---|---|
| `Guard` | **能不能挖**（所有挖都要先问它）。`ofTheSea` 是全局总闸的判断：头在水下只能挖这些，见 `UNDERWATER_PLAN.md` 最后一节 |
| `Placement` | **能不能放**：规划搭桥和真正放下问的是同一个，拒绝都带原因 |
| `Rules` | 开放 / 严格规则 |
| `Restrictions` | 服务器可以临时打开的限制：不挖不放某些方块、不过传送门。默认全关 |
| `ProtectionZones`, `ZoneExit`, `ZoneDisplay` | 保护区块；只靠区块表算出走出保护区的路；用粒子给玩家标出边界 |

### 改原版 `mixin/`

| 文件 | 作用 |
|---|---|
| `MobMixin` | 苦力怕不把它当目标 |
| `SleepStatusMixin` | 睡觉不算它 |
| `ItemEntityMixin` | 捡东西前问它要不要；捡了什么记下来，整理背包只扔它自己捡的 |
| `AxeItemAccessor`, `ConcretePowderBlockAccessor` | 读去皮表、混凝土粉末变成什么（给 `Interactions`） |

|---|---|

## 出 bug 时去哪找

| 现象 | 多半在 |
|---|---|
| 卡住、走歪、悬空、掉坑 | `MovementController`（走路线、看门狗）、`WalkStep`/`Body`（执行和碰撞）或 `LocalPathfinder`（规划） |
| 水下：憋气、换气 | `BotPlayer.breathe`（什么时候、怎么换气），`Air`/`Escape`（够不够） |
| 水下：路线、目标选择 | `LocalPathfinder.airAfter`，`RouteSearch`，`GatherTask.spent` |
| 说到不了，其实到得了（或反过来） | `RouteSearch.endLocked` / `endWay`，`OutOfReach` |
| 打怪不对 | `BotPlayer.combat`（自卫），`HuntTask.chase`（打猎） |
| 东西没捡 | `DropFetch`（地上的东西当来源）、`ItemEntityMixin`（要不要） |
| 挖了没掉东西 | `GatherTask.mine`（挖之前核对手里的东西）、`GatherTask.checkDrop`（日志里的"异常"） |
| 计划很蠢（舍近求远） | `CraftPlanner` 的成本 |
| 去远处找，方向或高度不对 | `Explorer`、`FarBiome`、`Habitat` |
| 挖了或放了不该动的 | `Guard`、`Placement` |
| 说"找不到 / 做不了" | 知识层 |
| 卡服 | `/bot perf`，再看 `PERF_BACKLOG.md` |
