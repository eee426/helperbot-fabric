# HelperBot 架构

服务端约 1.6 万行，分 5 层。**上层只调用下层，下层不知道上层的存在。**

```
 玩家
  │  /bot 指令、右键打开背包
  ▼
┌──────────────────────────────────────────────────────────┐
│ ① 入口层   HelperBot, command/BotCommands, BotInventoryMenu │  听玩家说什么
└──────────────────────────────────────────────────────────┘
  │ 创建任务
  ▼
┌──────────────────────────────────────────────────────────┐
│ ② 任务层   task/*                                          │  "要做什么"
│   AcquireTask（总指挥）→ GatherTask / HuntTask / CraftStep  │
│                          / SmeltStep / FetchWaterTask      │
└──────────────────────────────────────────────────────────┘
  │ 查资料                          │ "走到那里""挖这块""放这块"
  ▼                                 ▼
┌───────────────────────┐   ┌──────────────────────────────┐
│ ③ 知识层 knowledge/*   │   │ ④ 身体层  bot/*               │  "怎么做"
│ 东西从哪来、怎么做出来 │   │ BotPlayer：生存优先级         │
│ （只读游戏数据）       │   │ MovementController：走/挖/放  │
└───────────────────────┘   │ Loot：捡掉落物  Sight：视线   │
                            └──────────────────────────────┘
                                    │ 找路           │ 能不能挖/放
                                    ▼                ▼
                            ┌──────────────┐  ┌──────────────┐
                            │ ⑤ 寻路 path/* │  │ ⑤ 规则 guard/*│
                            └──────────────┘  └──────────────┘
```

依赖只能往下走，同层之间也不能绕回来：

| 这一层 | 可以用 | 不能用 |
|---|---|---|
| `guard` | 只用游戏本身 | 其他所有层 |
| `path` | `guard` | `knowledge`、`bot`、`task` |
| `knowledge` | `path`、`guard` | `bot`、`task` |
| `bot` | `path`、`guard` | `knowledge`、`task` |
| `task` | 以上全部 | |

下层要用上层的东西时，把它放到下层：`bot/BotTask` 是身体层定的接口，任务层来实现；`guard/InDimension` 是规则层定的接口，`path/Snapshot` 来实现。各层都可以用 `HelperBot.LOGGER`，它只是日志，不算依赖。

## ① 入口层：听玩家说什么

| 文件 | 作用 |
|---|---|
| `HelperBot` | 模组启动：注册指令、右键事件，服务器启动时预热知识层 |
| `command/BotCommands` | 所有 `/bot ...` 指令，把玩家的话翻译成一个任务 |
| `bot/BotManager` | 生成、删除机器人，加载它的存档数据 |
| `bot/BotInventoryMenu` | 右键打开的背包界面 |
| `bot/FakeConnection` | 假的网络连接（机器人没有客户端） |
| `bot/NameGuard`, `bot/ZoneReminder` | 每秒看一次：有人冒用机器人的名字；机器人在场但一个保护区块都没有 |

## ② 任务层：要做什么

每个任务每帧被调用一次，返回"还在做 / 做完了 / 失败了"。

| 文件 | 作用 |
|---|---|
| `AcquireTask` | **总指挥**。`/bot get` 用它：问知识层要一份计划，一步步执行，每做完一步重新规划 |
| `GatherTask` | 找到某种方块，走过去，挖之前核对手里的东西，挖（掉落物交给 Loot） |
| `HuntTask` | 找到会掉这种东西的生物，追上去打死（捡掉落物交给 Loot）。找不到时按生物怎么出现来办：动物先去 1000 格内最近的"它最多的群系"（按原版生成数据算出哪些群系最多），没有就在 500 格内按群系密度挑地方找，怪物找黑暗处等（白天露天就等天黑），特殊生物直接说明 |
| `CraftStep` / `SmeltStep` / `Station` | 合成、熔炼；需要时自己放工作台/熔炉，用完收回 |
| `FetchWaterTask` | 打一桶水（特殊：要找水面） |
| `ComeTask` | `/bot come`：走到玩家身边 |
| `MineCost` | 这只机器人挖这一块要花多少：用它手里的工具和气，给采集目标排序 |

## ③ 知识层：东西从哪来（不动世界，只读游戏数据）

| 文件 | 回答的问题 |
|---|---|
| `DropAnalysis` | 挖哪种方块会掉这个东西？用什么工具？ |
| `MobDrops` | 打哪种生物会掉这个东西？它在哪些群系出生？ |
| `RecipeIndex` | 哪些配方能做出这个东西？ |
| `CraftPlanner` | 综合以上，**算出最省事的计划**（挖/打/合成/熔炼的顺序） |
| `BiomeHints` | 每个群系每个区块平均有多少某种方块：来自地物的放置次数和大小、地表规则、低温结冰。只算“放下的方块”，不算“作为条件的方块” |
| `BlockScanner` | 附近已加载的区块里有没有 |
| `Obtainability` | 这东西生存模式能拿到吗？（基岩、命令方块直接拒绝） |
| `Interactions` | 对方块或生物用东西能得到什么：斧子的去皮表、混凝土粉末遇水变成什么、每种流体的桶、桶能装起的方块（细雪），以及拿桶、水桶、碗对每种生物用一下的结果（造一个不放进世界的生物、假玩家去用，问游戏要答案）。玻璃瓶装水和空地图只写在游戏代码里，单独写明 |
| `WhereFrom` | 每个物品从哪来：只靠主世界、要去地狱、要去末地、拿不到。和规划器“世界里有没有”同一套推法，按维度各算一遍（各维度自己的群系、结构、生物），方块要有能做出来的普通工具才算（精准采集不算）。给遥控器的选物品界面用（`/bot where`） |
| `StructureIndex` | 哪些结构里有什么：结构 → 模板池 → 模板，读出方块和生物。全部来自游戏数据，模组结构同样适用。规划器只在别处拿不到时才去结构里找 |

## ④ 身体层：怎么做

### BotPlayer：每帧的优先级（最重要的一张表）

每帧从上往下问，**谁说"我在忙"，下面的就都不执行**：

| 顺序 | 层 | 什么时候接管 |
|---|---|---|
| 1 | 换气 `breathe` | 水下快没气了；游不出去时才能挖开头顶 |
| 2 | 自卫 `combat` | 有怪在打它（远程 10 格内 / 近战够得着） |
| 3 | 吃东西 `tryEat` | 饿了（边走边吃） |
| 4 | 捡掉落物 `Loot` | 任务挖掉的方块、打死的怪掉了它要的东西（按"出现时间"跟踪，飘走、滚远都认得；水下先不追正在上浮的，到水面再一起捡） |
| 5 | 整理背包 `tidyInventory` | 背包快满了 |
| 6 | 任务 `task.tick` | 以上都没事 |
| — | 移动 `movement.tick` | 每帧最后执行，真正挪动身体 |

上层（自卫、捡东西）要临时去别的地方时，用 `engage` 借用移动；结束时用 `disengage` 把任务原来的目的地还回去。

### 移动的四个模块

| 文件 | 只负责 |
|---|---|
| `MovementController` | 跟着路线走：对外的 `goTo`、`status`、`follow`，走一步、卡住处理、借用移动 |
| `RouteSearch` | 选哪种搜索、怎么看结果：全量搜索、窗口、洪水、保护区、边走边想 |
| `Hands` | 挖和放，全局总闸的执行层，工具选择 |
| `Body` | 碰撞、重力、摔伤、浮沉、直接往上游 |

## ⑤ 底层

| 文件 | 作用 |
|---|---|
| `path/LocalPathfinder` | A* 寻路：在一块范围内找一串"走/跳/挖/搭桥/垫柱/游泳"的步骤；水下每个节点还带着"剩余空气" |
| `path/Air`, `path/Escape` | **水下的气量规则**：空气预算（剩余空气 + 允许扣的血）必须够它从当前位置出水；`Escape` 算"从这格游到能呼吸要多少刻"，不算挖。寻路、换气、选目标都用它 |
| `path/MineSpot` | **站在哪能挖到这一块**：选目标、规划器、走过去都问它，所以说法不会不一致 |
| `path/Mode` | 安全 / 普通 / 激进三种模式的参数 |
| `path/BreakTimes`, `BuildingBlocks` | 挖一块要多久；哪些方块可以拿来搭路 |
| `guard/Guard` | **能不能挖、能不能放**（所有挖和放都要先问它）。`ofTheSea` 是全局总闸的判断：头在水下只能挖这些，见 `UNDERWATER_PLAN.md` 最后一节 |
| `guard/Rules`, `ProtectionZones` | 开放/严格规则；保护区 |
| `mixin/*` | 改原版的三处：苦力怕不炸它、睡觉不算它、捡东西前问它要不要 |

## 出 bug 时去哪找

| 现象 | 多半在 |
|---|---|
| 卡住、走歪、悬空、掉坑 | `MovementController`（走路线）、`Body`（碰撞）或 `LocalPathfinder`（规划） |
| 水下：憋气、换气 | `BotPlayer.breathe`（什么时候、怎么换气），`Air`/`Escape`（够不够） |
| 水下：路线、目标选择 | `LocalPathfinder.airAfter`，`RouteSearch`，`GatherTask.spent` |
| 打怪不对 | `BotPlayer.combat` |
| 东西没捡 | `Loot`（所有掉落物的跟踪和拾取）、`ItemEntityMixin`（要不要） |
| 挖了没掉东西 | `GatherTask.mine`（挖之前核对手里的东西）、`GatherTask.checkDrop`（日志里的"异常"） |
| 计划很蠢（舍近求远） | `CraftPlanner` 的成本 |
| 挖了不该挖的 | `Guard` |
| 说"找不到 / 做不了" | 知识层 |

先看 `/bot log`，里面每条都能对应到上面某一层。
